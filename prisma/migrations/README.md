# История миграций PostgreSQL

Упорядоченная история переходов между версиями схемы БД.

## Содержимое

- `migration_lock.toml` фиксирует PostgreSQL как провайдер миграций.
- [20261007000000_initial](20261007000000_initial/README.md) — начальная схема.
- Новые каталоги создаёт Prisma Migrate; внутри каждой миграции хранится `migration.sql`.

## Правила и ограничения

- Добавляйте изменения отдельной миграцией с понятным названием и сохраняйте порядок применения.
- Не изменяйте SQL, имена или контрольные суммы миграций, уже применённых к БД.
- Проверяйте не только создание таблиц, но и перенос данных, индексы, внешние ключи и ограничения.
- SQL-ограничения, которые не выражены в Prisma-схеме, также являются частью модели хранения; не удаляйте их при последующих изменениях.
- Здесь не хранятся runtime-запросы, seed или дампы с пользовательскими данными. SQL-миграции исключены из Prettier.

## Проверки

Проверяйте применение цепочки на отдельной БД через `bun run db:deploy`. Для изменений схемы дополнительно проверяйте генерацию клиента и интеграционные сценарии.

Общие правила: [AGENTS.md](../../AGENTS.md). Родительский каталог: [README.md](../README.md).
