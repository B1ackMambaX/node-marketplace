# Схемы HTTP-контракта

Проверка и нормализация входа через Zod и описание сериализованных ответов для OpenAPI.

## Содержимое

- `*.schema.ts` — схемы авторизации, категорий, товаров/SKU, модерации, каталога, корзины и заказов.
- `common.schema.ts` — общая пагинация.
- `responses.schema.ts` — явно заданные поля HTTP-ответов, ISO-даты и пагинация; используется для генерации документации, не добавляет runtime-валидацию ответов.

## Правила и ограничения

- Здесь проверяются форма, типы, допустимые значения и границы входа, но не наличие объектов в БД, владелец или актуальный остаток.
- Не добавляйте I/O или вызовы сервисов в схему валидации.
- Тела запросов используют строгие объекты, чтобы запрещать неожиданные управляющие поля.
- Схемы PATCH не должны устанавливать defaults для пропущенных полей или принимать пустое изменение.
- OpenAPI генерируется из этих схем; не дублируйте структуру полей в документации. Ограничения пользовательских `.refine()` дополняйте метаданными для документации.
- Согласовывайте схемы ответов с DTO и мапперами; деньги целые, количества положительные там, где речь о покупке.
- Регистрация допускает только BUYER/SELLER; Idempotency-Key проверяется как отдельный HTTP-заголовок.

## Проверки

Запускайте `bun test tests/validation.test.ts tests/openapi.test.ts`; при изменении формы запроса добавляйте соответствующий HTTP-сценарий.
