# OpenAPI-документация

Описание публичного HTTP-контракта для Swagger UI и машинных клиентов.

## Содержимое

- `openapi.ts` — сборка OpenAPI 3.0.3: генерация схем из Zod, описания маршрутов, авторизация и статусы ответов.
- Спецификация отдаётся через `/openapi.json` и отображается в `/docs`.

## Правила и ограничения

- Документируйте реализованный контракт, а не планируемую функциональность.
- Схемы запросов берутся из `../schemas/*.schema.ts`, схемы сериализованных ответов — из `../schemas/responses.schema.ts`. Генерация выполняется через встроенный `z.toJSONSchema()` при загрузке документа.
- Для запросов используется `io: input`, чтобы defaults не делали поля обязательными; для ответов — `io: output`. Даты в ответах описываются как ISO-строки.
- Ограничения из пользовательских `.refine()`, которые нельзя вывести автоматически, описывайте через `.meta()` или `.describe()` рядом с валидацией.
- Методы, пути, статусы, роли и бизнес-описания операций остаются явными; обновляйте их вместе с маршрутом и контроллером.
- Все ссылки на схемы должны разрешаться; параметры пути обязательны; ответы 204 не содержат JSON-тела.
- Сохраняйте описание ролей, идемпотентности, статусов, единиц денег и фильтрации каталога.
- В примерах нет реальных секретов или пользовательских данных; публичные схемы не раскрывают внутренние поля.

## Проверки

Запускайте `bun test tests/openapi.test.ts`; изменения поведения проверяйте также HTTP-тестами и просмотром Swagger.
