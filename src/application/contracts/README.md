# Контракты зависимостей приложения

Интерфейсы внешних возможностей, которые нужны прикладным сценариям. В архитектуре «порты и адаптеры» такие контракты называют портами; их реализации находятся в infrastructure.

## Содержимое

- `repositories.ts` — методы хранения и чтения сущностей.
- `unit-of-work.ts` — доступ к репозиториям внутри чтения и общей транзакции.
- `security.ts` — хеширование паролей/значений, токены и часы.
- `readiness.ts` — проверка готовности инфраструктуры.

## Правила и ограничения

- Описывайте потребности сценария, а не универсальную копию API Prisma.
- Сигнатуры используют доменные модели и прикладные DTO; не допускайте Express, ORM-аргументы, generated-типы и конкретные библиотеки.
- Здесь хранятся интерфейсы, а не подключения, секреты и реализации адаптеров.
- В callback `RepositoryContext.transaction()` все репозитории используют одну общую транзакцию. `read()` выполняет обычное чтение без гарантии единого снимка.
- Callback транзакции может выполняться повторно при конфликте сериализации; не помещайте в него необратимые внешние действия.
- При изменении контракта согласованно обновляйте сервис, инфраструктурную реализацию и тестовые подмены.

## Проверки

Проверяйте совместимость реализаций через TypeScript, тесты сервисов и тест границ слоёв.
