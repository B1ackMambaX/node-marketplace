# Исходный код приложения

Слоистый монолит: точка входа, сборка зависимостей и четыре слоя API.

## Содержимое

- `server.ts` — запуск сервера, подключения и обработка завершения процесса.
- `app.ts` — сборка приложения с реальными зависимостями.
- `dependencies.ts` — ручное внедрение зависимостей (DI): выбор адаптеров и передача их сервисам.
- [domain](domain/README.md), [application](application/README.md), [infrastructure](infrastructure/README.md), [presentation](presentation/README.md) — слои приложения.

## Правила и ограничения

- Корень `src` содержит сборку и жизненный цикл, а не бизнес-операции или SQL.
- Связывайте конкретные реализации в `dependencies.ts`; контроллеры и сервисы получают готовые зависимости.
- Домен независим; прикладной слой использует домен и контракты; HTTP и инфраструктура не зависят друг от друга.
- Не создавайте зависимости от корневой сборки внутри слоёв: это обход их границ.
- `src/generated` создаётся Prisma и не редактируется вручную; собственная документация хранится вне generated-кода.

## Проверки

Для изменений кода: `bun run typecheck`, `bun run lint`, `bun run format:check` и соответствующие тесты. Границы зависимостей проверяет `tests/architecture.test.ts`.

Общие правила: [AGENTS.md](../AGENTS.md). Родительский каталог: [README.md](../README.md).
